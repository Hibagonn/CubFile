# トラブルシューティング

実装されているメッセージと設定に沿った確認です。ここに無い現象は、ログの文章を残してから調べてください。

## CubFile が起動しない

1. タスクバーとタスクマネージャーに CubFile が残っていないか見ます。残っていれば、それが前面に出るだけで、2つ目は起動しません。
2. 「別のWindowsセッションで起動しています」と出たときは、そのセッションの CubFile を使います。
3. 「ウィンドウを前面に表示できませんでした」と出たときは、タスクバーの CubFile を確認します。新しくは起動していません。
4. どのメッセージもなく何も出ないときは、配布 ZIP の `CubFile.exe` を起動しているか、Source code の書庫を開いていないかを確認します。

詳しくは [重複起動](../settings/single-instance.md) です。

## LAN の機器が表示されない

検索への表示をオフにしていないか、両方で LAN 転送が有効か、同じネットワークにいるかを確認します。手順は [接続できないとき](../network/connection-failures.md) です。

## 接続できない

**設定 > ネットワーク** の接続テストを実行します。失敗時の「オフラインか、IPが変わっている可能性があります。」は、相手の起動とアドレスの変更を示します。ポートの初期値は 45820 です。

## 転送が始まらない

- 貼付モードが予約貼付になっていないか。
- コピー先のパネルに青い枠があるか。
- 相手の共有フォルダと権限があるか。
- 接続テストが成功しているか。

予約に入っているだけのときは [転送予約](../network/reservation.md) から実行します。

## 進捗表示が変わらない

自動表示をオフにしていると、ウィンドウは開きません。ログを見るか、進捗ウィンドウを手動で開きます。数字が止まったときは、相手の応答と、ファイルが他のアプリで開かれていないかを確認します。

## アイコンが更新されない

アイコンセットの変更は再起動後です。再起動前は古い絵のままです。

## 設定が反映されない

**OK** または **適用** を押したかを確認します。パネルの方向は次のパネル追加時、ウィンドウサイズは次回起動時、という注記が設定画面にあります。データ保存先へ書けないときは、「設定データの保存先にアクセスできません。」という案内に従い、標準のローカルフォルダへ戻します。そのとき設定は初期化されません。

## ライセンスが認識されない

登録の直後は再起動が必要です。「再起動するとPlusが有効になります。」と出たあとに再起動します。固定ビルドではエディションは変わりません。キーを再入力し、失敗メッセージを確認します。

## 自動アップデートできない

ブラウザで GitHub Releases が開けるかを確認します。自動更新が無効のビルドでは、通知と手動更新だけが使えます。手動の手順は [手動更新](../updates/manual.md) です。

## 複数起動できない

仕様です。同じ Windows ユーザーでは1つだけ起動します。設定で許可する項目はありません。Updater とライセンス発行ツールは対象外です。
